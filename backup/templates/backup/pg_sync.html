2. Sync SQLite → PostgreSQL

Creates any missing tables with Django migrations on the PostgreSQL database, then deletes all app data there and copies every table and row from the live SQLite database (IDs, booleans, JSON, dates kept exact; ID sequences reset). Runs in one PostgreSQL transaction: on failure nothing is changed there. The live SQLite database is only read. Note: PostgreSQL stores JSON as jsonb, so key order and spacing inside JSON fields may be normalised (values are identical).

{% csrf_token %}

3. Sync PostgreSQL → SQLite

Builds a new SQLite file from PostgreSQL (schema by Django migrations, then every table and row) in BACKUP_DIR\pg_clones\ as a disk backup. PostgreSQL is only read. Optionally the clone then replaces the live db.sqlite3: a verified, protected ZIP backup of the live database is always taken first, and run_windows.bat must be restarted afterwards.

{% csrf_token %}

Long syncs keep this tab loading until done; the result summary appears above. Command-line equivalent: manage.py pg_sync --to-postgres / manage.py pg_sync --to-sqlite [--replace-live] (asks for the phrase).
